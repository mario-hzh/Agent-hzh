## 题目 3：多账号复盘与 Leader 指导 Agent
### 1. 需求解读
#### 业务背景
运营人员同时维护多个 X 账号，需要周期性复盘账号表现，定位账号问题，输出可落地执行动作，同时输出管理者视角的运营指导提纲；并且持续跟踪建议采纳之后账号指标变化，持续迭代复盘逻辑。

#### Agent 目标
输入至少 3 个目标账号与时间窗口，自动完成数据处理、账号问题诊断、根因定位，输出账号评分报告、下周落地动作、Leader 对运营的一对一指导提纲；跟踪建议执行后的业务变化，形成完整反馈闭环。

### 2. 工作流设计
整体分为 4 个阶段：数据采集 → 诊断分析 → 交付物生成 → 反馈闭环跟踪

#### 数据采集（工具调用层）
- 人工输入：账号 ID、分析时间窗口
- 模拟拉取账号推文、曝光、点赞、转发、回复、粉丝波动等表现数据；做数据清洗，剔除异常样本
- 记忆模块存储历史复盘记录，用于跨周期对比

#### 诊断分析（大模型推理层）
- 将结构化数据输入大模型，对比账号自身历史基准与行业参考基准
- 识别每个账号 1‑3 个核心问题，并做根因归类：选题 / 内容结构 Hook / 发布节奏 / 互动运营 / 账号健康度
- 多维度输出账号综合评分：内容质量、分发表现、账号健康、粉丝增长

#### 全套交付物生成
- 账号问题诊断，附带对应数据证据
- 下周账号可落地具体执行动作清单
- Leader 视角，面向运营同学的一对一沟通指导提纲
- 完整周期复盘报告

#### 反馈闭环跟踪
- Agent 输出报告后流转人工审核；人工标记每条建议「采纳 / 驳回」，填写简单原因
- 下一个周期读取新业务数据，对比采纳建议后的指标改善情况
- 将「建议‑执行‑效果」存入记忆，迭代后续诊断逻辑，减少无效建议

### 3. UI 理念
本 Agent 为后台业务分析智能体，无图形交互 UI 界面。全部输入输出以 Markdown 文档作为载体，输入为账号配置与数据表，输出为复盘报告、行动清单、指导文档。

### 4. AI 使用方式
1. 大模型：负责数据解读、问题根因推理、生成运营行动项、生成管理者指导提纲
2. 工具模拟：模拟数据拉取工具、记忆存储模块；本原型不调用真实外部 API，全部使用本地样本
3. 记忆模块：保存历史复盘报告、人工反馈记录，用于迭代分析逻辑

### 5. 人工审核 / 干预节点
1. 账号列表、分析时间窗口由人工指定；
2. Agent 仅输出报告，绝不自动操作账号，所有执行动作必须人工确认执行；
3. 人工标记建议采纳或驳回，录入反馈；
4. 大盘突发事件、平台算法改动、异常数据波动，由人工修正 Agent 诊断结论。

### 6. 当前局限
1. 仅能基于公开可获取内容数据，无法获取平台私部分发权重、广告投放数据，存在信息缺口；
2. 无法自动识别大盘热点、平台算法改版，容易把外部环境波动误判为账号本身问题；
3. 根因判断属于大模型概率推理，存在误判风险，不能完全替代资深运营专家判断。

### 7. 更多时间优先优化方向
1. 接入热点数据源，区分账号自身问题和大盘环境扰动；
2. 沉淀大量历史复盘样本，优化评分体系与根因判断规则，提升诊断准确率；
3. 增加置信度标签，对低置信度结论做高亮，提示运营重点复核；
4. 工程化：基于 Codex/WorkBuddy 封装成可运行程序，实现自动化读取本地数据批量生成报告。

## 题目 5：爆款内容拆解与二次创作 Agent
### 1. 需求解读
#### 业务背景
海外 X 账号运营，需要分析爆款推文，和同账号普通内容做对照，沉淀可复用的内容洞察与结构模板，产出原创候选内容，存入内容资产库；并且跟踪后续发布之后的真实表现，反向迭代拆解逻辑。

#### Agent 目标
输入目标账号，筛选爆款样本与对照组普通内容；完成爆款要素拆解、归因分析，沉淀可复用内容结构；基于底层洞察生成至少 3 条全新原创内容，做抄袭风险校验，存入内容资产库；接收人工审核与线上数据反馈形成闭环。

> 约束：只复用底层洞察，禁止简单改写洗稿。

### 2. 工作流设计
整体分为 5 个阶段：样本获取分组 → 对比拆解分析 → 原创生成 + 风控校验 → 入库资产库 → 效果反馈闭环

#### 样本获取与分组（工具调用）
- 人工设定账号 ID、爆款筛选阈值、时间窗口
- 模拟拉取推文，分为两组：A 组高表现爆款，B 组同账号普通低表现内容作为对照组
- 记忆模块保存全部原始样本

#### 对比拆解分析（大模型推理）
- A/B 两组对照分析，拆解选题、Hook、行文结构、信息密度、CTA、互动设计；
- 识别驱动爆款的真实核心因素，过滤偶然爆火因素（偶遇热点、大 V 转发）；
- 沉淀可复用内容结构模板，只保留洞察与叙事框架，不复制原文。

#### 差异化原创生成 + 风控校验
- 基于沉淀洞察模板，生成≥3 条全新原创推文；附带每条内容的底层洞察说明、目标受众；
- 模拟相似度检测工具，校验抄袭风险，相似度超标则重新生成。

#### 存入内容资产库
- 将原始样本、拆解报告、内容模板、生成候选内容统一入库；
- 对内容打上标签：选题分类、目标受众、适用场景，便于检索复用。

#### 效果反馈闭环
- 候选内容提交人工审核，人工标记采纳发布 / 驳回；
- 发布后，定期读取真实表现数据；
- 根据实际效果迭代：优化后续的爆款拆解、内容生成逻辑。

### 3. UI 理念
本 Agent 为内容分析生成智能体，无图形交互 UI 界面。全部输入输出以 Markdown 文档为载体，输出包含拆解报告、内容模板、候选推文、资产库记录。

### 4. AI 使用方式
1. 大模型：A/B 对照拆解爆款要素、沉淀内容模板、生成原创推文；
2. 工具模拟：推文样本拉取、相似度查重工具、内容资产库存储；原型全部基于本地样本模拟；
3. 记忆模块：保存历史样本、模板、已发布内容的效果数据。

### 5. 人工审核 / 干预节点
1. 爆款筛选阈值、样本范围由人工配置；
2. Agent 生成的候选内容，必须人工审核，Agent 不直接发布内容；
3. 人工完成事实核查，标记偶然爆款特例，避免沉淀无效模板；
4. 人工判定内容采纳、驳回。

### 6. 当前局限
1. 很难 100% 区分 “内容质量本身” 和外部助推因素（热点、大 V 转发），存在沉淀无效模板风险；
2. AI 生成海外内容容易存在事实错误、本地圈层文化理解偏差，必须人工核查；
3. 相似度检测仅做基础校验，无法完全规避洗稿风险。

### 7. 更多时间优先优化方向
1. 接入热点事件数据源，识别外部扰动，过滤偶然性爆款；
2. 增加事实校验工具，核查 AI 生成内容信息真实性；
3. 积累多垂类海外样本，优化本地化表达；
4. 工程化落地，基于 Codex/WorkBuddy 实现本地可运行版本。
